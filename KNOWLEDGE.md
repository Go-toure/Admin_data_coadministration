# What the admin data system knows

Generated by `python admin.py rules --markdown`. The rules live in `add_coadmin_columns.py`; this is their catalogue.


## Co-administration

- **coadmin**: Same district, round and Response with an nOPV2 record and a bOPV record are merged into one 'nOPV2 & bOPV' record; TotalNbrVaccPolio = the larger of the two (same children). A combined record gets the same total in both columns until the country gives the split.  
  Source: Feedback from Valentina Bigoni, WHO AFRO. Switch: `(always)`.
- **unused-vaccine**: A vaccine that was not used has an EMPTY total and coverage (not 0). Real reported zeros are kept.  
  Source: Decision 30 Oct 2026 (Ahmed's convention). Switch: `(always)`.

## Population

- **poppolio**: PopPolio is corrected from vaccinated / CVPolio when coverage is impossible (above 1.5, or below 0.5 with a plausible CVPolio); decimals rounded; otherwise the district median of the year; then a gradient-boosting estimate (listed for confirmation).  
  Source: Quality work with the focal points. Switch: `--no-fix-poppolio, --no-model-poppolio`.

## Copy / drag-fill errors

- **copy-repair**: A Response of another country, or nOPV3..nOPV15, is restored in this order: the LOOKUP (country + vaccine + start date), the newest earlier backup, the other rows of the same country/date/round, the campaign footprint. Only unique answers are used; the rest is UNRESOLVED.  
  Source: The lookup is the primary reference (your rule). Switch: `--no-repair, --no-infer`.
- **copied-rounds**: Rounds that the lookup does not have and that only copy another round of the same Response and date are removed and listed.  
  Source: Found in the 2026 data. Switch: `--keep-copied-rounds`.

## Key fields

- **response-fill**: An empty Response is filled from the lookup (exact start date, or within 21 days with the same round number), only when unique.  
  Source: Portal check 'Missing key field'. Switch: `--no-fill-response`.
- **response-names**: A Response that is not a lookup name but starts the name of the one lookup round of that country within 7 days is renamed to the lookup's spelling (MLW-2026-02-1_nOPV -> MLW-2026-02-1_nOPV-NID).  
  Source: Decision 30 Oct 2026: follow the lookup. Switch: `--no-align-response-names, --align-response-names COUNTRY`.

## Coverage

- **cvpolio**: An empty CVPolio is filled with TotalNbrVaccPolio / PopPolio. Records with only a target (no vaccinated) stay empty.  
  Source: Request of 28 Oct 2026. Switch: `--no-fill-cvpolio`.

## Districts

- **district-fill**: An empty District is filled from a recovered file, matched on country + Response + round + province: same PopPolio and total; same PopPolio and total within 10%; same total; total + the target implied by the coverage; the last unmatched pair; same PopPolio or total with unique pairing.  
  Source: Ethiopia file AFRO-ETH FIVE REGIONS R1 (282 of 282 filled). Switch: `--district-source FILE`.
- **addis**: Addis Ababa rows that repeat the sub-city name (NIFAS SILK LAFTO x13) are renamed '<SUB-CITY> WOREDA NN' from the file, only when every row of the sub-city matches a different woreda. Rows without a source (round 2 and 4 sub-cities of round 1) are left; they stay possible duplicates until a woreda-level file exists.  
  Source: Request of 29 Oct 2026. Switch: `(with --district-source)`.

## Geography

- **province**: A Province that belongs to another country (per geo_reference.csv) is corrected when certain.  
  Source: Admin portal checks. Switch: `--no-fix-province`.

## Hygiene

- **text-clean**: Stray control characters (carriage returns), line breaks and double / edge spaces in Country, Province, District, Response, Vaccine_type and Round_Add are removed.  
  Source: Found in District (KAJIADO EAST) 30 Oct 2026. Switch: `--no-clean-text`.
- **dates**: SIA_date written as text ('18-sept-20') becomes a real date.  
  Source: Admin portal. Switch: `(always)`.
- **duplicates**: Exact copies are removed; records with the same key but different values are NOT removed, only reported (Duplicate record). Key = Country, Province, District, [Admin_3], SIA_date, Round_Add, Vaccine_type, Response.  
  Source: Admin portal. Switch: `--no-dedupe, --resolve-duplicates`.

## Checks

- **quality**: The portal quality checks (missing key field, coverage above the ceiling, target jumps, report date, province/country, co-administration consistency, vaccine spelling, duplicates) produce a report with Errors / Warnings / Info.  
  Source: Admin portal (run_admin_quality_check.R). Switch: `--no-quality`.

## Decisions and standing rules

- The lookup file is the primary reference for campaign names, dates and rounds; backups come second.
- Never guess: an answer is used only when it is unique; otherwise the record is left and listed.
- A build always starts from the live SharePoint file, so nobody's newer edits are lost.
- SharePoint keeps no version history (the local backup has it); one published file, replaced in place.
- The data dictionary (AFRO_admin_data_dictionary.xlsx) is pushed with every publish, into the existing SharePoint file; the previous live one is kept in workspace/dictionary_backups. A dictionary problem never undoes the published data (exit 3, retry with `admin.py dictionary`).
- Data is never committed to git (only lookup.xlsx and geo_reference.csv). No attribution lines in commit messages.
- Each code change is its own commit, followed by its own push.
- Open questions kept visible: Addis Ababa round 2 and 4 sub-cities lack woreda names (need a woreda-level file); Tegedie exists in two zones of Amhara with the same name; about 1,460 Nigeria 2022-Jan 2023 records have no Response in the lookup.
